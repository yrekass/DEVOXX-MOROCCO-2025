vers une documentation vivante et utile

Tech Lead/Développeur

Problématique

  • Documentation dispersée (Confluence, Notion, README Git)
  • Dérive entre code et docs
  • Difficulté d'accès pour les devs

Qu'est-ce que Backstage ?

Plateforme de developer experience pour gérer services, catalogues et docs.

TechDocs — vue d'ensemble

  • Plugin officiel Backstage
  • Génère une documentation statique à partir de Markdown (MkDocs)
  • Docs versionnées dans le repo du composant

Architecture (schéma)

Repo Git → MkDocs (docs/) → CI/CD → Storage (S3/GCS) → Backstage TechDocs Backend → UI

Étapes d'intégration — résumé

  1. Ajouter mkdocs.yml
  2. Ajouter docs/ (Markdown)
  3. Ajouter annotation TechDocs dans catalog-info.yaml
  4. Configurer backend TechDocs (app-config.yaml)

Démo — Scénario rapide (6 min)

Objectif : montrer de l'import d'un composant -> visualiser TechDocs dans Backstage -> modifier et re-générer

Fichiers-clés (exemples)

# mkdocs.yml
site_name: Mon Service
nav:
  - Accueil: index.md
  - API: api.md

# catalog-info.yaml (extrait)
metadata:
  name: mon-service
  annotations:
    backstage.io/techdocs-ref: dir:./docs

Commandes utiles (CI & local)

# Exemple local / git
git clone git@github.com:org/mon-service.git
cd mon-service
# éditer docs/index.md
git add docs/index.md
git commit -m "Ajout intro TechDocs"
git push

# Si vous utilisez Backstage local
cd backstage
yarn dev

# Extrait CI (pseudo)
- name: Build TechDocs
  run: mkdocs build -d site
- name: Upload to S3
  run: aws s3 sync site/ s3://bucket/mon-service/

Bénéfices & bonnes pratiques

  • Docs versionnées avec le code
  • Visibilité centralisée pour les équipes
  • Automatisation via CI/CD
  • Templates MkDocs partagés et revue PR pour docs
