Backstage + TechDocs

Rendre la documentation naturelle — intégrée au quotidien des équipes

Docs · Backstage · TechDocs

Problème

  • Docs éparpillées (Confluence, Notion, GitHub, Google Doc...)
  • Souvent obsolètes ou difficiles à trouver
  • Les devs n’aiment pas quitter leur workflow

Idée clé

Et si la documentation était produite là où le code vit — dans Git, via des PR, visible dans le portail développeur ?

Docs as Code → adoption naturelle

Backstage (en 1 minute)

  • Portail développeur open source (Spotify)
  • Catalogue des services / composants
  • Intégration d'outils & plugins
Pourquoi ?

Centraliser l'expérience dev : observabilité, docs, CI, templates — tout accessible au même endroit.

TechDocs — le plugin Docs-as-Code

  • Rend les docs Markdown visibles dans Backstage
  • Stock dans Git, versionné via PR
  • Génération statique (MkDocs) + hébergement via Backstage

Avant vs Après

AvantAprès (TechDocs)
Docs éparpilléesDocs centralisées dans Backstage
Pas de versioningGit + PR + CI
Mise à jour manuelleÉditable depuis repo — pipeline build

Ce que voient les devs

Dans Backstage :
  • Onglet Docs sur chaque composant
  • Recherche globale
  • Liens vers sources

Démo — scénario (slides)

  1. Ouvrir Backstage → sélectionner un composant
  2. Afficher l'onglet Docs
  3. Montrer le repo source (docs/index.md)
  4. Faire une modif rapide en PR → merge → voir le rendu

(Garder la démo courte : 6–8 minutes max)

Arguments pour convaincre

  • Adoption : les devs restent dans Git/Backstage
  • Qualité : review + versioning
  • Découverte : recherche centralisée

Plan d'adoption en 4 étapes

  1. Choisir 1 équipe pilote
  2. Migrer 1 repo de doc vers docs/ en Markdown
  3. Configurer TechDocs + CI (build MkDocs)
  4. Mesurer usage & itérer

Bonnes pratiques

  • Faire d'une PR de features une PR de docs
  • Templates de pages (onboarding, runbooks, archi)
  • Tags / metadata dans catalog-info.yaml

Risques & solutions

  • "Trop de docs" → indexation + search
  • Obsolescence → règles PR + ownership
  • Mauvaise qualité → templates & linting Markdown
